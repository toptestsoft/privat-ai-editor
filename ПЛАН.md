# ПЛАН: Заработок на AI-инструментах без вложений

**Профиль:** технарь + умеешь ставить локальные модели (LM Studio, qwen) + много времени + фокус на универсальные цифровые штуки.
**Бюджет:** 0 ₽. **Язык:** русский. **Дата:** 2026-08-25.

---

## Концепция (одной строкой)
Делаем **бесплатные универсальные AI-инструменты, работающие приватно в браузере** (через локальные модели WebGPU/transformers.js), собираем на них аудиторию и монетизируем разовыми платежами (донаты + продажа готовых паков промптов/шаблонов ботов + кастомные боты под заказ).

---

## Почему это сработает (на основе исследования, см. ИССЛЕДОВАНИЕ.md)
1. **Бесплатный хостинг навсегда.** Hugging Face *Static Spaces* и GitHub Pages отдают статические сайты (в т.ч. with WebGPU/transformers.js) бесплатно, без карты. Это твой «сервер» за 0₽.
2. **Твой дефицитный навык = локальные модели.** 90% «заработчиков на ИИ» умеют только облачные API. Приватность без подписок — реальная боль (кейс: обработка медзаписей локально). Ты это умеешь.
3. **Тренд монетизации в РФ-2025:** донаты выросли в 3×, подписки падают (Boosty −11%, Patreon −50%). → Делаем упор на **разовые платежи**, а не на подписку.
4. **Реальные прецеденты:** курс по AI-промптам продан 1000× по $50 → $500–5000+/мес (Habr).

### Что в прототипе
- Два режима работы: **«Мой LM Studio»** (твой локальный ИИ, приватно) и **«Браузерная модель»** (WebGPU/transformers.js — приватно у любого посетителя без сервера).
- 4 действия: сократить, перефразировать, выделить ключевое, перевести.
- Кнопки поддержки (Boosty/DonationAlerts) — ссылки подставим под ник.

### ВАЖНО 1: thinking-модели (пустой ответ)
- `qwen3.5-9b` (твоя дефолтная) — **thinking-модель**: отдаёт пустой контент (весь бюджет токенов уходит в размышления), даже с `enable_thinking:false` на RX 6600 она пустая за 81с.
- ✅ Рабочая модель для live-редактирования: **`gemma-4-e4b-it`** — отвечает по-русски за ~15–22с.
- Поэтому в приложении: дефолт `gemma-4-e4b-it`, выбор модели в UI, авто-отключение thinking для qwen3.x, понятная ошибка если модель вернула пусто.

### ВАЖНО 2: WebGPU недоступен в части браузеров → сделан CPU-фолбэк
- Ошибка `Failed to get GPU adapter` значит, что браузер/система не дали WebGPU (на твоей машине Chromium-snap headless его нет; у части пользователей тоже).
- ✅ Исправлено: режим «Браузерная модель» сначала пробует WebGPU, при отказе **автоматически переключается на CPU (WASM)** — работает в любом браузере, просто медленнее (модель ~0.5GB грузится из CDN).
- Основной путь заработка — режим **«Мой LM Studio»** (твой локальный ИИ, быстро, приватно) — от WebGPU не зависит и уже проверен.
- Для конечных пользователей браузерный режим = «открой и попробуй, даже без LM Studio», но он тяжёлый (загрузка модели). Главный сценарий демо — показывать свой LM Studio.

### Как запустить локально (для теста)
```
cd ~/projects/ai-monetization/app
python3 serve.py          # прокси на http://localhost:8080
```
Открыть http://localhost:8080/ → в LM Studio загрузить gemma-4-e4b-it, включить Server + CORS.
Прокси нужен, т.к. браузерный fetch к localhost:1234 блокируется CORS; через :8080 origin совпадает.
**Проверено:** логика fetch к LM Studio возвращает корректную суммаризацию (HTTP 200, реальный русский текст).
